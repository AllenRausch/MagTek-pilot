# 3.3.1 TLV Encoding

### Introduction

TLV (Tag-Length-Value) encoding is the fundamental data format used in all DynaFlex device communication. Every command you send, every response you receive, and every piece of data exchanged uses TLV encoding. Understanding TLV is essential for working with DynaFlex devices.

**In this article:**

* What TLV encoding is and why it's used
* How to read and write TLV-encoded data
* Step-by-step examples of encoding and decoding
* Common TLV patterns you'll encounter
* How to work with nested and complex TLV structures

**Who should read this:**

* All developers integrating DynaFlex devices
* Anyone working with payment device APIs
* Developers troubleshooting data format issues
* Technical architects reviewing integration designs

### What is TLV Encoding?

**TLV encoding** is a method for organizing data where each piece of information is packaged as three parts:

1. **Tag** - Identifies _what_ the data represents
2. **Length** - Specifies _how much_ data follows
3. **Value** - Contains the _actual data_

#### Real-World Analogy

Think of TLV encoding like a warehouse full of labeled boxes:

**Without TLV (chaos):**

```
A pile of items with no organization:
"10.00" "USD" "12345678" "John Smith" "Approved"
↑ What are these? What order? How do we know where each item ends?
```

**With TLV (organized):**

```
📦 Box labeled "AMOUNT" → Contains: "10.00"
📦 Box labeled "CURRENCY" → Contains: "USD"  
📦 Box labeled "ACCOUNT" → Contains: "12345678"
📦 Box labeled "NAME" → Contains: "John Smith"
📦 Box labeled "STATUS" → Contains: "Approved"
```

Each box (TLV triplet) is:

* **Labeled** (Tag) - so you know what's inside
* **Sized** (Length) - so you know how big the contents are
* **Filled** (Value) - with the actual information

This makes it easy to:

* Find specific data without reading everything
* Add new data types without breaking existing code
* Skip data you don't need
* Validate data integrity

#### Key Characteristics

TLV encoding has several important characteristics:

* **Self-describing:** Each piece of data identifies itself with a tag
* **Flexible:** New tags can be added without breaking existing parsers
* **Efficient:** Only transmit the data you need
* **Parseable:** Can skip unknown tags without errors
* **Extensible:** Supports nested structures for complex data

### Why TLV is Used in Payment Devices

TLV encoding is an industry standard for payment devices because:

1. **EMV Specification:** EMV chip cards use TLV for all data exchange
2. **ISO Standards:** Based on ISO/IEC 7816-4 international standard
3. **Flexibility:** Supports evolving payment standards without protocol changes
4. **Interoperability:** All payment devices and processors understand TLV
5. **Error Tolerance:** Unknown tags can be safely ignored

**Important:** While you could communicate using other formats, TLV is required for EMV compliance and compatibility with payment networks.

### How TLV Encoding Works

#### The Basic Structure

Every TLV consists of three consecutive parts:

```
┌─────────────────────────────────────────────┐
│  TAG                                        │
│  1 or 2 bytes                               │
│  Identifies what this data represents       │
├─────────────────────────────────────────────┤
│  LENGTH                                     │
│  1 or 2 bytes                               │
│  Specifies how many bytes of data follow    │
├─────────────────────────────────────────────┤
│  VALUE                                      │
│  Variable length (specified by Length)      │
│  The actual data                            │
└─────────────────────────────────────────────┘
```

#### Tag Field

**Purpose:** Identifies what the data represents

**Size:** 1 or 2 bytes

* Single byte tags: `0x01` to `0xFF` (except reserved ranges)
* Two byte tags: Start with `0xDF` or other reserved prefixes

**Examples:**

```
0x80 = Transaction Amount
0x81 = Merchant ID  
0x82 = Transaction Type
0xDF01 = Custom tag (two bytes)
```

**Tag Numbering:**

* Tags `0x01` - `0x7F`: Single byte, simple tags
* Tags `0x80` - `0xFE`: Single byte, context-specific
* Tags starting with `0xDF`, `0xFF`, etc.: Two-byte extended tags

#### Length Field

**Purpose:** Specifies how many bytes of data follow in the Value field

**Size:** 1 or 2 bytes

* If length ≤ 127 bytes: Use 1 byte
* If length > 127 bytes: Use 2 bytes (first byte indicates this)

**One-byte length (value 0-127):**

```
0x05 = 5 bytes follow
0x10 = 16 bytes follow  
0x7F = 127 bytes follow
```

**Two-byte length (value > 127):**

```
0x81 0x80 = 128 bytes follow (0x81 means "one more byte of length follows")
0x81 0xFF = 255 bytes follow
0x82 0x01 0x00 = 256 bytes follow (0x82 means "two more bytes follow")
```

**How to read two-byte length:**

* First byte starting with `0x8` indicates extended length
* The lower nibble tells you how many more bytes to read
* `0x81` = 1 more byte, `0x82` = 2 more bytes, etc.

#### Value Field

**Purpose:** Contains the actual data

**Size:** Exactly the number of bytes specified in the Length field

**Data types:**

* **Binary:** Raw bytes (device serial number, cryptograms)
* **Integer:** Numeric values in big-endian format
* **Text:** UTF-8 or ASCII strings
* **BCD:** Binary Coded Decimal (for amounts)
* **Nested TLV:** Another TLV structure inside this value

### Step-by-Step TLV Examples

#### Example 1: Simple TLV (Transaction Amount)

Let's encode: **Transaction Amount = $10.00**

**Step 1: Choose the tag**

```
Tag for Amount = 0x80
```

**Step 2: Prepare the value**

```
Amount in cents = 1000
In hex = 0x03E8
Size = 2 bytes
```

**Step 3: Calculate length**

```
Value is 2 bytes
Length = 0x02
```

**Step 4: Assemble the TLV**

```
Tag:    80
Length: 02
Value:  03 E8

Complete TLV: 80 02 03 E8
```

**Breakdown:**

```
80    = Tag: Transaction Amount
02    = Length: 2 bytes of data follow
03 E8 = Value: 1000 in hexadecimal
```

#### Example 2: Text TLV (Merchant Name)

Let's encode: **Merchant Name = "Joe's Shop"**

**Step 1: Tag**

```
Tag for Merchant Name = 0x81
```

**Step 2: Value**

```
Text: "Joe's Shop"
In ASCII hex: 4A 6F 65 27 73 20 53 68 6F 70
Length: 10 bytes
```

**Step 3: Length**

```
10 bytes = 0x0A
```

**Step 4: Assemble**

```
Tag:    81
Length: 0A
Value:  4A 6F 65 27 73 20 53 68 6F 70

Complete TLV: 81 0A 4A 6F 65 27 73 20 53 68 6F 70
```

#### Example 3: Long Value (Card Number)

Let's encode: **PAN = 4111111111111111** (16 digits)

**Step 1: Tag**

```
Tag for PAN = 0x5A
```

**Step 2: Value**

```
Card number: 4111111111111111
In BCD format: 41 11 11 11 11 11 11 11
Length: 8 bytes
```

**Step 3: Length**

```
8 bytes = 0x08
```

**Step 4: Assemble**

```
Tag:    5A
Length: 08
Value:  41 11 11 11 11 11 11 11

Complete TLV: 5A 08 41 11 11 11 11 11 11 11
```

#### Example 4: Two-Byte Tag

Let's encode: **Custom Field = "TEST"**

**Step 1: Tag (two bytes)**

```
Custom tag = 0xDF01
```

**Step 2: Value**

```
Text: "TEST"
In ASCII: 54 45 53 54
Length: 4 bytes
```

**Step 3: Length**

```
4 bytes = 0x04
```

**Step 4: Assemble**

```
Tag:    DF 01
Length: 04
Value:  54 45 53 54

Complete TLV: DF 01 04 54 45 53 54
```

#### Example 5: Extended Length (> 127 bytes)

Let's encode: **Long data = 200 bytes of data**

**Step 1: Tag**

```
Tag = 0x90
```

**Step 2: Value**

```
Data: [200 bytes of data]
Length: 200 bytes = 0xC8
```

**Step 3: Extended Length**

```
200 > 127, so we need two-byte length:
First byte:  0x81 (indicates 1 more byte follows)
Second byte: 0xC8 (the actual length: 200)
```

**Step 4: Assemble**

```
Tag:    90
Length: 81 C8 (extended length format)
Value:  [200 bytes of data]

Complete TLV: 90 81 C8 [200 bytes...]
```

### Multiple TLVs in Sequence

Real messages contain multiple TLVs one after another:

#### Example: Complete Transaction Request

**Data to encode:**

* Amount: $10.00 (1000 cents)
* Transaction Type: Purchase (0x00)
* Merchant ID: "MERCH001"

**Encoding each TLV:**

**TLV 1 - Amount:**

```
Tag:    80
Length: 02
Value:  03 E8
Result: 80 02 03 E8
```

**TLV 2 - Transaction Type:**

```
Tag:    82
Length: 01
Value:  00
Result: 82 01 00
```

**TLV 3 - Merchant ID:**

```
Tag:    81
Length: 08
Value:  4D 45 52 43 48 30 30 31 (ASCII: "MERCH001")
Result: 81 08 4D 45 52 43 48 30 30 31
```

**Complete message (all three TLVs):**

```
80 02 03 E8 82 01 00 81 08 4D 45 52 43 48 30 30 31
```

**How to read this:**

```
Position  Bytes           Meaning
0-3:      80 02 03 E8     Tag 80, Length 2, Value 1000
4-6:      82 01 00        Tag 82, Length 1, Value 0  
7-16:     81 08 ...       Tag 81, Length 8, Value "MERCH001"
```

### Parsing TLV Data

#### The Parsing Algorithm

To read TLV-encoded data:

```
1. Read Tag (1 or 2 bytes)
2. Read Length (1 or 2+ bytes)
3. Read Value (exactly Length bytes)
4. Move to next TLV
5. Repeat until end of data
```

#### Code Example: TLV Parser

```csharp
public class TLVParser
{
    public static List<TLV> Parse(byte[] data)
    {
        var tlvList = new List<TLV>();
        int pos = 0;
        
        while (pos < data.Length)
        {
            // Read Tag
            int tag = data[pos++];
            
            // Check if two-byte tag
            if ((tag & 0x1F) == 0x1F)
            {
                tag = (tag << 8) | data[pos++];
            }
            
            // Read Length
            int length = data[pos++];
            
            // Check if extended length
            if ((length & 0x80) != 0)
            {
                int numLengthBytes = length & 0x7F;
                length = 0;
                
                for (int i = 0; i < numLengthBytes; i++)
                {
                    length = (length << 8) | data[pos++];
                }
            }
            
            // Read Value
            byte[] value = new byte[length];
            Array.Copy(data, pos, value, 0, length);
            pos += length;
            
            // Store TLV
            tlvList.Add(new TLV
            {
                Tag = tag,
                Length = length,
                Value = value
            });
        }
        
        return tlvList;
    }
}

public class TLV
{
    public int Tag { get; set; }
    public int Length { get; set; }
    public byte[] Value { get; set; }
    
    public override string ToString()
    {
        return $"Tag: 0x{Tag:X}, Length: {Length}, Value: {BitConverter.ToString(Value)}";
    }
}
```

#### Usage Example

```csharp
// Parse TLV data
byte[] data = new byte[] { 
    0x80, 0x02, 0x03, 0xE8,        // Amount
    0x82, 0x01, 0x00,              // Type
    0x81, 0x08, 0x4D, 0x45, 0x52,  // Merchant ID
              0x43, 0x48, 0x30, 0x30, 0x31
};

var tlvList = TLVParser.Parse(data);

foreach (var tlv in tlvList)
{
    Console.WriteLine(tlv.ToString());
}

// Output:
// Tag: 0x80, Length: 2, Value: 03-E8
// Tag: 0x82, Length: 1, Value: 00
// Tag: 0x81, Length: 8, Value: 4D-45-52-43-48-30-30-31
```

### Nested TLV Structures

Some values contain TLVs within them - this is called **nested TLV**.

#### Example: Encrypted Data Container

The outer TLV contains an encrypted container, and inside that container are more TLVs:

```
┌──────────────────────────────────────────┐
│  Tag: FF (Encrypted Container)           │
│  Length: 20                              │
│  Value: [Encrypted data]                 │
│    ┌────────────────────────────────┐    │
│    │ After decryption:              │    │
│    │ Tag: 5A, Length: 8             │    │
│    │ Value: [Card number]           │    │
│    │                                │    │
│    │ Tag: 5F24, Length: 3           │    │
│    │ Value: [Expiration date]       │    │
│    └────────────────────────────────┘    │
└──────────────────────────────────────────┘
```

**Hex representation:**

```
Outer TLV:
FF 14 [20 bytes encrypted data]

After decryption, inner TLVs:
5A 08 41 11 11 11 11 11 11 11
5F 24 03 25 12 31
```

#### Working with Nested TLVs

```csharp
public class NestedTLVParser
{
    public static void ParseNested(byte[] data)
    {
        var outerTLVs = TLVParser.Parse(data);
        
        foreach (var tlv in outerTLVs)
        {
            Console.WriteLine($"Outer Tag: 0x{tlv.Tag:X}");
            
            // Check if this is a container tag
            if (tlv.Tag == 0xFF)  // Encrypted container
            {
                // Decrypt the value
                byte[] decrypted = Decrypt(tlv.Value);
                
                // Parse inner TLVs
                var innerTLVs = TLVParser.Parse(decrypted);
                
                foreach (var innerTlv in innerTLVs)
                {
                    Console.WriteLine($"  Inner Tag: 0x{innerTlv.Tag:X}");
                    Console.WriteLine($"  Inner Value: {BitConverter.ToString(innerTlv.Value)}");
                }
            }
        }
    }
    
    private static byte[] Decrypt(byte[] encrypted)
    {

        // This is just a placeholder
        return encrypted;
    }
}
```

### Common TLV Patterns in DynaFlex

#### Pattern 1: Simple Data Fields

Most common - single-value data:

```
Tag 80: Amount        → Always 2-4 bytes, integer
Tag 82: Type          → Always 1 byte, enum
Tag 81: Merchant ID   → Variable length, text
```

#### Pattern 2: Encrypted Containers

Sensitive data wrapped in encryption:

```
Tag FF: Encrypted Container
  ├─ Contains encrypted data
  └─ After decryption: multiple inner TLVs
      ├─ Tag 5A: PAN
      ├─ Tag 5F24: Expiration
      └─ Tag 5F20: Cardholder Name
```

#### Pattern 3: Optional Parameters

Some TLVs may or may not be present:

```
Required:
  Tag 80: Amount          (always present)
  Tag 82: Type            (always present)

Optional:
  Tag 83: Options         (only if options specified)
  Tag 84: Metadata        (only if metadata provided)
```

#### Pattern 4: Repeating TLVs

Same tag appearing multiple times:

```
Tag 90: Item 1 data
Tag 90: Item 2 data  
Tag 90: Item 3 data
```

### TLV Best Practices

#### **Recommended Practices:**

**Reading TLV Data:**

* **Always parse dynamically** - Never hardcode positions
* **Use the length field** - Don't assume value sizes
* **Handle unknown tags gracefully** - Skip tags you don't recognize
* **Validate length before reading value** - Prevent buffer overruns
* **Check bounds** - Ensure you don't read past end of data

**Writing TLV Data:**

* **Calculate length correctly** - Count actual bytes in value
* **Use correct tag numbers** - Refer to documentation
* **Pad if required** - Some values need specific lengths
* **Order matters sometimes** - Check if tag order is specified
* **Test with real device** - Verify encoding is accepted

**Performance:**

* **Cache parsed TLVs** - Don't re-parse repeatedly
* **Use efficient data structures** - Dictionary for tag lookups
* **Reuse buffers** - Minimize allocations in hot paths
* **Parse only what you need** - Skip irrelevant tags early

#### **Common Pitfalls**

**Parsing Errors:**

* **Don't assume single-byte tags** - Check for extended tags
* **Don't assume single-byte length** - Check for extended length
* **Don't hardcode tag positions** - Data order can vary
* **Don't ignore length field** - Reading wrong amount causes errors
* **Don't parse without bounds checking** - Can read past end of buffer

**Encoding Errors:**

* **Don't forget to update length** - Must match actual value size
* **Don't mix up tag endianness** - Multi-byte tags are big-endian
* **Don't confuse tag with value** - Tag identifies, value contains
* **Don't forget trailing data** - Some TLVs have padding
* **Don't assume tag uniqueness** - Same tag can appear multiple times

**Data Type Errors:**

* **Don't assume text is ASCII** - May be UTF-8
* **Don't assume integers are same size** - Check length field
* **Don't forget BCD encoding** - Amounts often use BCD
* **Don't mix binary and text** - Each tag has a defined type## Debugging TLV Data

#### Visualizing TLV Structure

```csharp
public class TLVVisualizer
{
    public static void VisualizeTLV(byte[] data, int indent = 0)
    {
        int pos = 0;
        string indentStr = new string(' ', indent * 2);
        
        while (pos < data.Length)
        {
            // Read tag
            int tagStart = pos;
            int tag = data[pos++];
            if ((tag & 0x1F) == 0x1F && pos < data.Length)
            {
                tag = (tag << 8) | data[pos++];
            }
            
            // Read length
            int lengthStart = pos;
            int length = data[pos++];
            if ((length & 0x80) != 0 && pos < data.Length)
            {
                int numBytes = length & 0x7F;
                length = 0;
                for (int i = 0; i < numBytes && pos < data.Length; i++)
                {
                    length = (length << 8) | data[pos++];
                }
            }
            
            // Validate we have enough data
            if (pos + length > data.Length)
            {
                Console.WriteLine($"{indentStr}ERROR: Length {length} exceeds remaining data");
                break;
            }
            
            // Read value
            int valueStart = pos;
            byte[] value = new byte[length];
            Array.Copy(data, pos, value, 0, length);
            pos += length;
            
            // Display
            Console.WriteLine($"{indentStr}Tag: 0x{tag:X4} (pos {tagStart})");
            Console.WriteLine($"{indentStr}Length: {length} (pos {lengthStart})");
            Console.WriteLine($"{indentStr}Value: {BitConverter.ToString(value).Replace("-", " ")}");
            
            // Try to interpret value
            Console.WriteLine($"{indentStr}  As Integer: {TryParseInt(value)}");
            Console.WriteLine($"{indentStr}  As Text: {TryParseText(value)}");
            Console.WriteLine();
        }
    }
    
    private static string TryParseInt(byte[] value)
    {
        if (value.Length == 0 || value.Length > 8) return "N/A";
        
        long result = 0;
        foreach (byte b in value)
        {
            result = (result << 8) | b;
        }
        return result.ToString();
    }
    
    private static string TryParseText(byte[] value)
    {
        try
        {
            string text = System.Text.Encoding.UTF8.GetString(value);
            return text.All(c => !char.IsControl(c) || char.IsWhiteSpace(c)) 
                ? $"\"{text}\"" 
                : "N/A";
        }
        catch
        {
            return "N/A";
        }
    }
}

// Usage:
byte[] tlvData = new byte[] { 0x80, 0x02, 0x03, 0xE8, 0x82, 0x01, 0x00 };
TLVVisualizer.VisualizeTLV(tlvData);

// Output:
// Tag: 0x0080 (pos 0)
// Length: 2 (pos 1)
// Value: 03 E8
//   As Integer: 1000
//   As Text: N/A
//
// Tag: 0x0082 (pos 4)
// Length: 1 (pos 5)
// Value: 00
//   As Integer: 0
//   As Text: N/A
```

#### Common TLV Errors and How to Fix Them

**Error: "Length exceeds buffer"**

```
Problem: Length field says 100 bytes, but only 50 remain
Cause: Corrupted data or incorrect parsing
Fix: Validate total message length before parsing
```

**Error: "Unknown tag 0xXX"**

```
Problem: Parser encounters unfamiliar tag
Cause: New firmware, different device, or corruption
Fix: Skip unknown tags gracefully - this is normal!
```

**Error: "Value doesn't match expected type"**

```
Problem: Tag 80 (amount) contains text instead of number
Cause: Wrong tag used, or value not properly encoded
Fix: Check tag documentation, verify encoding
```

```html
<!DOCTYPE html>
<html>
<head>
    <title>TLV Decoder</title>
</head>
<body>
    <h1>TLV Hex Decoder</h1>

        function decodeTLV() {
            const input = document.getElementById('hexInput').value;
            const hex = input.replace(/\s/g, '');
            const bytes = hex.match(/.{1,2}/g).map(b => parseInt(b, 16));
            
            let output = '';
            let pos = 0;
            
            while (pos < bytes.length) {
                const tag = bytes[pos++];
                const length = bytes[pos++];
                const value = bytes.slice(pos, pos + length);
                pos += length;
                
                output += `Tag: 0x${tag.toString(16).padStart(2, '0').toUpperCase()}\n`;
                output += `Length: ${length}\n`;
                output += `Value: ${value.map(b => b.toString(16).padStart(2, '0').toUpperCase()).join(' ')}\n`;

        }
```

### Summary

**Key Takeaways:**

* **TLV = Tag + Length + Value** - Three parts identifying, sizing, and containing data
* **Tags identify data types** - Like labels on boxes
* **Length specifies value size** - Can be 1 or 2+ bytes for extended lengths
* **Values contain actual data** - Exactly as many bytes as Length specifies
* **Multiple TLVs in sequence** - Real messages contain many TLVs one after another
* **Nested TLVs are common** - TLVs can contain other TLVs
* **Parse dynamically** - Never hardcode positions, always use length field
* **Skip unknown tags** - This is by design, allows forward compatibility

**Remember:** TLV encoding might seem complex at first, but it's actually quite simple once you understand the pattern: Read tag, read length, read that many value bytes, repeat. This format makes DynaFlex devices flexible, extensible, and compatible with industry standards.
